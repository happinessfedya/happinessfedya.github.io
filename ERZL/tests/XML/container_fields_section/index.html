    Тесты ContainerFieldsSection

    Эта страница показывает тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/xml/test_container_fields_section.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит свои сценарии, поэтому в pytest видны только имена тестов и статусы PASSED. Ниже раскрыто, какие именно XML-сценарии, controlled errors и архитектурные ограничения стоят за этими статусами.

    Докстринг модуля

    Тесты для `XML.xml_builder.ContainerFieldsSection`.

Модуль проверяет контракт leaf-writer секции create-flow: запись `XMLKVPairs`
в уже созданный namespaced-контейнер, поведение на пустых и дублирующихся
полях, а также проброс ожидаемых ошибок.

Файл нужен для фиксации того, что `ContainerFieldsSection` остаётся тупым
писателем XML-полей и не берёт на себя бизнес-валидацию create-сценария.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    ContainerFieldsSection живет в XML-слое и делает только одну вещь: записывает уже подготовленные пары name -> value в готовый XML-контейнер. Класс берет:

    • container, у которого уже должен быть namespace;
    • XMLKVPairs, где пары уже нормализованы и готовы к записи.

    На выходе он:

    • создает дочерние XML-элементы внутри container;
    • использует namespace самого контейнера;
    • записывает .text каждого leaf-узла.

    Этот класс не:

    • не выбирает create-операцию;
    • не валидирует бизнес-смысл полей;
    • не дедуплицирует повторяющиеся имена;
    • не управляет ERZL_id, RequestType или create-flow;
    • не скрывает low-level ошибки формы pairs и нестроковых значений.
