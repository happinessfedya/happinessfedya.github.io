    Тесты GetXMLAnswerAdapter

    Эта страница показывает наглядные сценарии из общего test-файла. В браузере Python не запускается: блоки Показать вызов раскрывают эталонный вывод, который дает команда:

    python -m pytest -vv -s tests/adapters/test_get_xml_answer_adapter.py

    Флаг -s нужен, чтобы pytest не скрывал печать сценариев и в документации были видны реальные блоки Вход, Вызов, Вывод и Ошибка.

    Докстринг модуля

    Наглядные тесты для `GetXMLAnswerAdapter`.

Модуль показывает типовые сценарии работы `rslt_container_to_ctx` на простых
подготовленных DTO, печатает состояние контейнера до и после вызова и
дополнительно фиксирует базовые контрактные ограничения адаптера.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот адаптер

    GetXMLAnswerAdapter стоит после XML parser. Parser возвращает временный XMLRsltContainer, а adapter переносит его содержимое в context.rslt_container.

    Метод класса:

    returned_value = adapter.rslt_container_to_ctx(context, rslt)

    Метод ничего не возвращает. Его результат — измененный context.rslt_container.

    Важно по типам:

    XMLRsltContainer.result: list[XMLFieldValDTO]
XMLFieldValDTO.container: list[XMLOneFieldVal]
XMLRsltContainer.mistakes: list[XMLErrorDTO]
XMLErrorDTO.container: list[XMLErrorVal]

    Первый тест: первый успешный response

    Докстринг теста

    Показывает добавление первого успешного response в пустой context.

    Первый тест показывает нам самый простой сценарий: context еще пустой, parser вернул один успешный findPersonsResponse, и adapter кладет его в context.rslt_container.result.

    У теста вывод именно такой потому что в context еще нет response с именем findPersonsResponse, поэтому создается первая верхнеуровневая запись XMLFieldValDTO.

    Второй тест: merge успешного response

    Докстринг теста

    Показывает накопление успешных полей внутри одного `response_name`.

    Второй тест показывает нам накопление данных по одному response. В context уже есть XMLFieldValDTO(response_name='findPersonsResponse') с id, а новый parser-result принес еще surnameInitials для того же response.

    У теста вывод именно такой потому что adapter не создает второй XMLFieldValDTO с тем же response_name, а дописывает новый XMLOneFieldVal в container уже существующего DTO.

    Третий тест: merge серверных ошибок

    Докстринг теста

    Показывает накопление серверных ошибок внутри одного `response_name`.

    Третий тест показывает нам такую же логику для mistakes. В context уже есть XMLErrorDTO(response_name='findPersonsResponse') с ошибкой 404, а новый parser-result принес ошибку 422 для того же response_name.

    У теста вывод именно такой потому что успешные данные и ошибки хранятся в разных списках, но внутри mistakes merge выполняется по тому же response_name.

    Показать код тестаСкрыть код теста 
    def test_rslt_container_to_ctx_merges_server_mistakes_by_name() -> None:
    """Показывает накопление серверных ошибок внутри одного `response_name`."""
    # Arrange
    existing = _mistake_result("findPersonsResponse", [("404", "Не найдено")])
    context = RsltContainerContextStub(
        rslt_container=XMLRsltContainer(mistakes=[existing])
    )
    incoming = XMLRsltContainer(
        mistakes=[
            _mistake_result("findPersonsResponse", [("422", "Некорректный id")])
        ],
    )
    adapter = GetXMLAnswerAdapter()
    before = XMLRsltContainer(
        mistakes=[_mistake_result("findPersonsResponse", [("404", "Не найдено")])]
    )
    existing_id = id(existing)

    # Act
    returned_value = adapter.rslt_container_to_ctx(context, incoming)

    # Assert
    assert returned_value is None
    assert id(context.rslt_container.mistakes[0]) == existing_id
    assert context.rslt_container == XMLRsltContainer(

    Четвертый тест: разные create responses

    Докстринг теста

    Показывает create-flow, где разные response хранятся раздельно.

    Четвертый тест показывает нам create-flow: в context уже есть положительный ответ от создания базовой персоны, а потом приходит положительный ответ от создания ДУЛ.

    У теста вывод именно такой потому что addUpdateNonresidentPersonResponse и addUpdateDudl20211008Response имеют разные response_name. Adapter не склеивает их между собой, а хранит как два разных XMLFieldValDTO внутри XMLRsltContainer.result.

    Пятый тест: result и mistakes вместе

    Докстринг теста

    Показывает независимое накопление `result` и `mistakes`.

    Пятый тест показывает нам, что adapter может обработать incoming container, в котором одновременно есть успешные данные и серверные ошибки.

    У теста вывод именно такой потому что result и mistakes объединяются независимо: успешный XMLOneFieldVal(container_name='sexId') дописывается в result, а ошибка XMLErrorVal(error_code='200') — в mistakes.

    Показать код тестаСкрыть код теста 
    def test_rslt_container_to_ctx_merges_success_and_mistakes_independently() -> None:
    """Показывает независимое накопление `result` и `mistakes`."""
    # Arrange
    context = RsltContainerContextStub(
        rslt_container=XMLRsltContainer(
            result=[_success_result("findPersonsResponse", [("id", "42")])],
            mistakes=[_mistake_result("findPersonsResponse", [("100", "old")])],
        )
    )
    incoming = XMLRsltContainer(
        result=[_success_result("findPersonsResponse", [("sexId", "1")])],
        mistakes=[_mistake_result("findPersonsResponse", [("200", "new")])],
    )
    adapter = GetXMLAnswerAdapter()
    before = XMLRsltContainer(
        result=[_success_result("findPersonsResponse", [("id", "42")])],
        mistakes=[_mistake_result("findPersonsResponse", [("100", "old")])],
    )

    # Act
    returned_value = adapter.rslt_container_to_ctx(context, incoming)

    # Assert
    assert returned_value is None
    assert context.rslt_container == XMLRsltContainer(
        result=[
            _success_result("findPersonsResponse", [("id", "42"), ("sexId", "1")])
