    Тесты RenameToSourceInputAdapter

    Эта страница показывает наглядные сценарии из общего test-файла. В браузере Python не запускается: блоки Показать вызов раскрывают эталонный вывод, который дает команда:

    python -m pytest -vv -s tests/adapters/test_rename_to_source_input_adapter.py

    Флаг -s нужен, чтобы pytest не скрывал печать сценариев и в документации были видны реальные блоки Вход, Вызов, Вывод и Ошибка.

    Докстринг модуля

    Наглядные тесты для `RenameToSourceInputAdapter`.

Модуль показывает типовые сценарии работы `adapt()` на реальных и намеренно
битых входных данных, печатает вход, вызов и результат или ошибку и
дополнительно фиксирует базовые контрактные ограничения адаптера.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот адаптер

    RenameToSourceInputAdapter стоит на границе Source -> Adapters. Он получает DTO строки источника с исходными заголовками и возвращает SourceInput с каноническими полями pipeline.

    Главный метод класса:

    result = adapter.adapt(source_row)

    Первый тест: базовое преобразование

    Докстринг теста

    Показывает базовый сценарий с переименованием известных и пропуском лишних колонок.

    Первый тест показывает нам основной сценарий: в строке источника есть две полезные колонки и одна служебная колонка. Адаптер берет только те заголовки, которые есть в rename_column_dict, и превращает их в PersonFields.

    У теста вывод именно такой потому что "Фамилия" и "Имя" описаны в конфиге переименования, а "Служебный комментарий" в конфиге отсутствует.

    Показать код тестаСкрыть код теста 
    def test_adapt_maps_known_headers_and_ignores_unmapped_header() -> None:

    # Arrange
    rename_column_dict = {
        "Фамилия": PersonFields.SURNAME,
        "Имя": PersonFields.NAME,
    }
    source_row = XLSMRowDTO(
        data={
            "Фамилия": "Иванов",
            "Имя": "Иван",
            "Служебный комментарий": "строка проверена оператором",
        },
        index=17,
    )
    adapter = _make_adapter(rename_column_dict)

    # Act
    result = adapter.adapt(source_row)

    # Assert
    assert result == SourceInput(
        attributes={
            PersonFields.SURNAME: "Иванов",
            PersonFields.NAME: "Иван",
        },
        index=17,
    )

    _print_success_case(
        title="RenameToSourceInputAdapter.adapt: базовое преобразование",
        source_row=source_row,
        rename_column_dict=rename_column_dict,

    )

    Второй тест: значения не нормализуются

    Докстринг теста

    Показывает перенос всех допустимых `SourceValue` без нормализации.

    Второй тест показывает нам границу ответственности адаптера. Он переименовывает ключи, но не нормализует значения вообще. Он одинаково пропускает дальше строку с пробелами, числа, False, datetime, date, time, timedelta и None.

    У теста вывод именно такой потому что все эти значения уже считаются допустимыми SourceValue, а задача адаптера на этом этапе только переименовать ключи и сохранить исходные значения без изменений.

    Третий тест: конфликт переименования

    Докстринг теста

    Показывает ошибку конфликта для двух колонок с одной mapping-целью.

    Третий тест показывает нам controlled error: две разные колонки источника пытаются попасть в одно каноническое поле PersonFields.SURNAME.

    У теста вывод именно такой потому что адаптер не должен silently overwrite-ить одно значение другим. Если обе колонки присутствуют во входе, такой конфликт останавливается через ValueError.

    Показать код тестаСкрыть код теста 
    def test_adapt_shows_conflict_error_for_two_headers_with_same_target() -> None:
    """Показывает ошибку конфликта для двух колонок с одной mapping-целью."""
    # Arrange
    rename_column_dict = {
        "Фамилия из XLSM": PersonFields.SURNAME,
        "Фамилия из внешней сверки": PersonFields.SURNAME,
    }
    source_row = XLSMRowDTO(
        data={
            "Фамилия из XLSM": "Иванов",
            "Фамилия из внешней сверки": "Петров",
        },
        index=19,
    )
    adapter = _make_adapter(rename_column_dict)

    # Act / Assert
    with pytest.raises(ValueError, match="Конфликт ключей") as exc_info:
        adapter.adapt(source_row)

    _print_error_case(
        title="RenameToSourceInputAdapter.adapt: конфликт переименования",
        source_row_data=source_row.data,
        source_row_index=source_row.index,
        rename_column_dict=rename_column_dict,
        call_text="result = adapter.adapt(source_row)",
        error=exc_info.value,
    )
    Показать вызовСкрыть вызов
    #### Вход 
    source_row.index = 19
source_row.data =
{
    'Фамилия из XLSM': 'Иванов',
    'Фамилия из внешней сверки': 'Петров',
}
rename_column_dict =
{
    'Фамилия из XLSM': PersonFields.SURNAME,
    'Фамилия из внешней сверки': PersonFields.SURNAME,
}
    #### Вызов 
    result = adapter.adapt(source_row)
    #### Ошибка 
    ValueError: Конфликт ключей при переименовании: 'Фамилия из внешней сверки' -> 'surname' уже существует

    Четвертый тест: нарушение SourceData_Protocol

    Докстринг теста

    Показывает ошибку для DTO, который не выполняет `SourceData_Protocol`.

    Четвертый тест показывает нам ошибку контракта DTO источника. Для адаптера обязательны data и index; если index отсутствует, адаптер не может создать корректный SourceInput.

    У теста вывод именно такой потому что это не бизнес-ошибка данных пациента. Это ошибка структуры DTO, который пришел из Source-слоя.

    Показать код тестаСкрыть код теста 
    def test_adapt_shows_protocol_error_when_source_row_has_no_index() -> None:
    """Показывает ошибку для DTO, который не выполняет `SourceData_Protocol`."""
    # Arrange
    rename_column_dict = {"Фамилия": PersonFields.SURNAME}
    broken_source_row = BrokenSourceDtoWithoutIndex(data={"Фамилия": "Иванов"})
    adapter = _make_adapter(rename_column_dict)

    # Act / Assert
    with pytest.raises(AttributeError) as exc_info:
        adapter.adapt(cast(SourceData_Protocol, broken_source_row))

    _print_error_case(
        title="RenameToSourceInputAdapter.adapt: DTO источника без index",
        source_row_data=broken_source_row.data,
        source_row_index="<отсутствует>",
        rename_column_dict=rename_column_dict,
        call_text="result = adapter.adapt(source_row)",
        error=exc_info.value,
    )
    Показать вызовСкрыть вызов

source_row.data =
{
    'Фамилия': 'Иванов',
}
rename_column_dict =
{
    'Фамилия': PersonFields.SURNAME,
}
    #### Вызов 
    result = adapter.adapt(source_row)
    #### Ошибка
