    Тесты RenameXmlKVPairsAdapter

    Эта страница показывает наглядные сценарии из общего test-файла. В браузере Python не запускается: блоки Показать вызов раскрывают эталонный вывод, который дает команда:

    python -m pytest -vv -s tests/adapters/test_rename_xml_kv_pairs_adapter.py

    Флаг -s нужен, чтобы pytest не скрывал печать сценариев и в документации были видны реальные блоки Вход, Вызов, Вывод и Ошибка.

    Докстринг модуля

    Наглядные тесты для `RenameXmlKVPairsAdapter`.

Модуль показывает типовые сценарии работы методов
`build_from_source_fields()` и `rename_XMLKVPairs_from_ctx()`, печатает вход,
вызов, результат или ошибку и дополнительно фиксирует базовые контрактные
границы адаптера.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот адаптер

    RenameXmlKVPairsAdapter стоит на границе Adapters -> XML. Он берет уже нормализованные PersonFields из source/context, выбирает поля текущей попытки и строит XMLKVPairs для XML builder.

    У класса два рабочих метода:

    result = adapter.build_from_source_fields(source, selected_fields)

    и context-обертка:

    result = adapter.rename_XMLKVPairs_from_ctx(context)

    Первый тест: базовая сборка XMLKVPairs

    Докстринг теста

    Показывает базовый сценарий преобразования выбранных полей в `XMLKVPairs`.

    Первый тест показывает нам основной сценарий: в source есть несколько канонических полей, но текущая попытка выбрала только часть из них. Адаптер берет только selected_fields, переименовывает их через fields_rename и возвращает XMLKVPairs.

    У теста вывод именно такой потому что PersonFields.SURNAME и PersonFields.NAME выбраны для текущей попытки, а PersonFields.PATRONYMIC лежит в source, но не входит в selected_fields.

    # Arrange

        PersonFields.NAME: "Иван",

        selected_fields=selected_fields,

    Второй тест: подготовка значений к XML

    Докстринг теста

    Показывает приведение значений к `str` и `strip()` перед XML-слоем.

    Второй тест показывает нам важное отличие от RenameToSourceInputAdapter: перед XML-слоем значения уже приводятся к строке и очищаются через strip(). Это касается не только фамилии и даты рождения, а всего выбранного набора полей текущей попытки.

    У теста вывод именно такой потому что " Иванов " превращается в "Иванов", число 1 становится строкой "1", False становится "False", datetime и date сериализуются в текст, а timedelta превращается в строку "2 days, 0:05:00".

    Третий тест: сборка из context

    Докстринг теста

    Показывает context-обертку, удобную для вызова после `DataSelector`.

    Третий тест показывает нам метод rename_XMLKVPairs_from_ctx(). Его удобно вызывать после DataSelector: context уже содержит все нормализованные данные в SourceData и набор полей текущей попытки в DataAttemptStr.

    У теста вывод именно такой потому что context-метод является тонкой оберткой над build_from_source_fields() и передает туда context.SourceData вместе с context.DataAttemptStr.

    Показать код тестаСкрыть код теста

    Четвертый тест: выбранного поля нет в source

    Докстринг теста

    Показывает ошибку, если выбранного поля нет в `SourceData`.

    Четвертый тест показывает нам controlled error: DataAttemptStr попросил поле, которого нет в SourceData. В таком состоянии нельзя строить XML, потому что XML builder получил бы неполный набор данных.

    У теста вывод именно такой потому что PersonFields.DATE_BIRTH есть в selected_fields, но отсутствует в source.

    Показать код тестаСкрыть код теста 
    def test_build_from_source_fields_shows_missing_source_key_error() -> None:
    """Показывает ошибку, если выбранного поля нет в `SourceData`."""
    # Arrange
    source = {PersonFields.SURNAME: "Иванов"}
    selected_fields = (PersonFields.SURNAME, PersonFields.DATE_BIRTH)
    adapter = _make_adapter()

    # Act / Assert
    with pytest.raises(RenameAndBuildXmlKVPairsError, match="не найден в source") as exc_info:
        adapter.build_from_source_fields(
            source=source,
            selected_fields=selected_fields,
        )

    _print_error_case(
        title="RenameXmlKVPairsAdapter.build_from_source_fields: выбранного поля нет в source",
        source=source,
        selected_fields=selected_fields,
        fields_rename=XML_FIELDS_RENAME,
        call_text="result = adapter.build_from_source_fields(source, selected_fields)",
        error=exc_info.value,
    )

    Пятый тест: значение равно None

    Докстринг теста

    Показывает ошибку, если выбранное значение равно `None`.

    Пятый тест показывает нам controlled error для невалидного значения. Если поле выбрано для XML, но значение равно None, адаптер останавливает сборку XMLKVPairs.

    У теста вывод именно такой потому что PersonFields.DATE_BIRTH присутствует в source, но его значение равно None.
