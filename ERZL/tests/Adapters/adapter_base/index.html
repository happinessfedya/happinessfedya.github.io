    Тесты AdapterBase

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/adapters/test_adapter_base.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит дополнительных строк, поэтому в консоли видны только имена тестов и статусы PASSED. Ниже раскрыто, какое именно состояние и какие ошибки фиксируют эти тесты.

    Докстринг модуля

    Контрактные тесты для `Adapters.Adapters.AdapterBase`.

Модуль проверяет безопасную мутацию `AttemptId`, раннюю runtime-валидацию
context и архитектурные границы базового adapter-слоя.

Тесты нужны для защиты минимального контракта `AdapterBase`, который должен
работать только с `AttemptId` и не смешивать эту логику с source-, XML- или
pipeline-ответственностью.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    AdapterBase — это минимальный общий adapter-слой для мутаций context, не завязанных на конкретную внешнюю систему. В текущем коде он отвечает только за работу со счетчиком попыток AttemptId.

    Этот класс:

    • увеличивает AttemptId на единицу;
    • сбрасывает AttemptId к ATTEMPT_ID_START;
    • рано валидирует наличие и тип AttemptId в context.

    Этот класс не:

    • не работает с SourceData, DataAttemptStr, PersonType или XML-данными;
    • не принимает pipeline-решения;
    • не требует конкретного dataclass-контекста, ему нужен только structural object с AttemptId.

    Пятый тест: bool принимается как подкласс int

    Докстринг теста

    Фиксирует текущее поведение Python: `bool` проходит проверку `isinstance(..., int)`.

    Пятый тест фиксирует очень конкретный Python-runtime нюанс. Поскольку isinstance(True, int) возвращает True, текущая проверка типа в AdapterBase принимает bool.

    Поэтому True читается как 1, после инкремента превращается в 2, и тест закрепляет именно это поведение.

    Восьмой тест: базовый adapter не трогает чужие слои context

    Докстринг теста

    Проверяет, что `AdapterBase` не влезает в XML, source-данные и pipeline branching.

    Последний тест защищает архитектурную границу класса. В теле AdapterBase не должно быть терминов вроде SourceData, xml_bytes, StepRslt или NEXT_ATTEMPT, потому что базовый adapter обязан работать только со счетчиком попыток.

    Именно поэтому тест анализирует исходный код класса через inspect.getsource.

    Показать код тестаСкрыть код теста 
    def test_adapter_base_class_body_does_not_touch_other_context_layers() -> None:
    """Проверяет, что `AdapterBase` не влезает в XML, source-данные и pipeline branching."""
    # Arrange
    class_source = inspect.getsource(AdapterBase)
    forbidden_terms = (
        "DataAttemptStr",
        "SourceData",
        "PersonType",
        "create_flags",
        "xml_bytes",
        "response_bytes",

        "NEXT_ATTEMPT",
        "NO_MORE_ATTEMPTS",
