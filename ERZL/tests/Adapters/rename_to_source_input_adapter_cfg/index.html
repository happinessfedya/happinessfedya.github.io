    Тесты RenameToSourceInputAdapterCfg

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/adapters/test_rename_to_source_input_adapter_cfg.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит дополнительных строк, поэтому в консоли видны только имена тестов и статусы PASSED. Ниже раскрыто, какой bootstrap-контракт конфигурации проверяет каждый тест.

    Докстринг модуля

    Контрактные тесты для `Adapters.adapters_core_types.RenameToSourceInputAdapterCfg`.

Модуль проверяет сборку alias-конфига на bootstrap-этапе, trim alias-ов,
валидацию enum-значений и защиту от конфликтной повторной привязки заголовков.

Тесты нужны для защиты bootstrap-контракта конфигурации, которая подготавливает
плоский `rename_column_dict` для последующего `RenameToSourceInputAdapter`.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    RenameToSourceInputAdapterCfg живет в adapters_core_types и хранит готовое отображение {source_header: canonical_field} для RenameToSourceInputAdapter.

    Этот конфиг:

    • собирается на bootstrap-этапе из словаря alias-ов;
    • разворачивает field_value -> [alias1, alias2] в плоский rename_column_dict;
    • валидирует, что field value существует в целевом enum;
    • защищает от пустых и конфликтующих alias-ов.

    Этот класс не:

    • не читает строки источника сам;
    • не адаптирует DTO в SourceInput;
    • не нормализует значения полей, он работает только с заголовками и их маппингом.

    Первый тест: bootstrap-конфиг разворачивается в плоский словарь

    Докстринг теста

    Проверяет разворот bootstrap-конфига в плоский словарь с enum-значениями.

    Первый тест показывает основной сценарий field_from_alias(): на входе есть словарь {canonical_value: [alias1, alias2, ...]}, а на выходе нужен уже быстрый плоский rename_column_dict.

    У теста вывод именно такой потому что оба alias-а фамилии должны указывать на один и тот же PersonFields.SURNAME, а значения в словаре обязаны быть именно элементами enum.

    Показать код тестаСкрыть код теста 
    def test_field_from_alias_builds_flat_mapping_with_enum_values() -> None:
    """Проверяет разворот bootstrap-конфига в плоский словарь с enum-значениями."""
    # Arrange
    alias_by_field = {
        PersonFields.SURNAME.value: ["Фамилия", "Фамилия пациента"],
        PersonFields.NAME.value: ["Имя"],
    }

    # Act
    cfg = RenameToSourceInputAdapterCfg.field_from_alias(alias_by_field, PersonFields)

    # Assert
    assert cfg.rename_column_dict == {
        "Фамилия": PersonFields.SURNAME,
        "Фамилия пациента": PersonFields.SURNAME,
        "Имя": PersonFields.NAME,
    }
    assert all(
        isinstance(field, PersonFields) for field in cfg.rename_column_dict.values()
    )

    #### Вход

    "surname": ["Фамилия", "Фамилия пациента"],
    "namep": ["Имя"],
}
field_enum = PersonFields
    #### Вызов 
    cfg = RenameToSourceInputAdapterCfg.field_from_alias(alias_by_field, PersonFields)
    #### Вывод
