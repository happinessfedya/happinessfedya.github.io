    Тесты ERZLAdapter

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/adapters/test_erzl_adapter.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит дополнительных строк, поэтому в консоли видны только имена тестов и статусы PASSED. Ниже раскрыто, какое именно runtime-состояние context и какие архитектурные границы фиксируют эти тесты.

    Докстринг модуля

    Контрактные тесты для `Adapters.Adapters.ERZLAdapter`.

Модуль фиксирует, что ERZL-специфичный adapter меняет только целевые
runtime-поля context: `PersonType`, `create_flags` и `ERZL_id`.

Тесты нужны для защиты узкого контракта `ERZLAdapter`, который должен
точечно менять ERZL-specific runtime-состояние и не смешивать эту логику с
source-, transport-, XML- или orchestration-ответственностью.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    ERZLAdapter живет в adapter-слое и отвечает за точечные мутации ERZL-специфичного runtime-context. По текущему коду у него есть только простые операции:

    • switch_person_type(ctx, type) меняет ctx.PersonType;
    • set_need_create(...), set_good_create_base(...), set_good_create_policy(...), set_good_create_DUDL(...), set_good_create_address(...) меняют отдельные флаги внутри ctx.create_flags;
    • reset_create_flags(ctx) целиком заменяет ctx.create_flags на новый CreateFlags();
    • set_ERZL_id(ctx, id) пишет ctx.ERZL_id.

    Этот класс:

    • меняет только PersonType, create_flags и ERZL_id;
    • не возвращает новый context;
    • работает со structural context-object, если у него есть нужные слоты.

    Этот класс не:

    • не трогает AttemptId, SourceData, DataAttemptStr;
    • не работает с xml_bytes, response_bytes и transport DTO;
    • не принимает orchestration-решения;
    • не делает низкоуровневую XML-логику.
