    Тесты ERZL_Context

    Эта страница показывает contract-тесты для ERZL_Context как документацию контракта. В браузере Python не запускается: блоки Показать вызов раскрывают сценарий и ожидаемое поведение, которое проверяет команда:

    python -m pytest -vv -s tests/source/test_erzl_context.py

    Флаг -s нужен, чтобы pytest не скрывал вывод успешно прошедших тестов.

    Зачем этот класс

    ERZL_Context стоит на границе Source → Adapters → XML → Orchestrator. Он создаётся один раз на строку источника и несёт в себе все данные, которые наполняются по мере прохождения через шаги пайплайна.

    Контекст создаётся через фабрику:

    factory = ERZLContextFactory()
context = factory.create_context(source_input)

    Первый тест: поля и значения по умолчанию

    Первый тест показывает нам полный набор полей ERZL_Context и их начальные значения: обязательные поля задаются при создании, а runtime-поля инициализируются в безопасные дефолты. У теста вывод именно такой потому что @dataclass(slots=True) фиксирует список полей, а default_factory обеспечивает свежие объекты при каждом создании контекста.

    Показать вызовСкрыть вызов
    #### Вход 
    source_data = {PersonFields.SURNAME: 'Ivanov'}
    #### Вызов 
    context = ERZL_Context(
    SourceData=source_data,
    index=1,
    PersonType=AllXMLFields.ERZL.OperationsStr.FindPersonsType.MOSCOW,
    AttemptId=ATTEMPT_ID_START,
)
    #### Вывод 
    field_names == (
    'SourceData', 'index', 'PersonType', 'AttemptId',
    'DataAttemptStr', 'xml_bytes', 'response_bytes',
    'rslt_container', 'ERZL_id', 'create_flags',
)
context.SourceData is source_data     → True
context.index                         → 1
context.AttemptId                     → ATTEMPT_ID_START
context.DataAttemptStr                → ()
context.xml_bytes                     → None
context.response_bytes                → None
context.rslt_container.result         → []
context.rslt_container.mistakes       → []
context.ERZL_id                       → None
context.create_flags == CreateFlags() → True

PASSED

    Второй тест: слоты запрещают неизвестные поля

    Второй тест показывает нам, что @dataclass(slots=True) не позволяет присвоить произвольное runtime-поле снаружи класса. У теста вывод именно такой потому что __slots__ не содержит имя unknown_runtime_field, и Python поднимает AttributeError.

    Показать вызовСкрыть вызов
    #### Вход 
    context = ERZL_Context(
    SourceData={PersonFields.SURNAME: 'Ivanov'},
    index=1,
    PersonType=AllXMLFields.ERZL.OperationsStr.FindPersonsType.MOSCOW,
    AttemptId=ATTEMPT_ID_START,
)
    #### Вызов 
    context.unknown_runtime_field = "unexpected"
    #### Ошибка 
    AttributeError: 'ERZL_Context' object has no attribute 'unknown_runtime_field'

PASSED

    Третий тест: независимые фабричные объекты у разных контекстов

    Третий тест показывает нам, что rslt_container и create_flags создаются независимо для каждого экземпляра ERZL_Context через default_factory. У теста вывод именно такой потому что если бы default использовался вместо default_factory, все контексты разделяли бы один контейнер и одни флаги.

    Показать вызовСкрыть вызов
    #### Вход 
    left_context  = ERZL_Context(SourceData={PersonFields.SURNAME: 'Ivanov'}, index=1, ...)
right_context = ERZL_Context(SourceData={PersonFields.SURNAME: 'Ivanov'}, index=1, ...)
    #### Вызов 
    left_context.rslt_container.result.append(
    XMLFieldValDTO(
        response_name='findPersonsResponse',
        container=[XMLOneFieldVal(container_name='erzlId', container_val='123')],
    )
)
left_context.create_flags.need_create = True
    #### Вывод 
    left_context.rslt_container is not right_context.rslt_container → True
left_context.create_flags   is not right_context.create_flags   → True
len(left_context.rslt_container.result)                         → 1
right_context.rslt_container.result                             → []
left_context.create_flags.need_create                           → True
right_context.create_flags.need_create                          → False

PASSED

    Четвёртый тест: фабрика создаёт контекст с каноническим начальным состоянием

    Четвёртый тест показывает нам, что ERZLContextFactory правильно инициализирует ERZL_Context из SourceInput. У теста вывод именно такой потому что фабрика устанавливает PersonType в MOSCOW и AttemptId в ATTEMPT_ID_START по умолчанию — именно так требует начало ERZL-пайплайна.

    Показать вызовСкрыть вызов
    #### Вход 
    source_data = {PersonFields.SURNAME: 'Ivanov', PersonFields.NAME: 'Ivan'}
input_data  = SourceInput(attributes=source_data, index=5)
factory     = ERZLContextFactory()
    #### Вызов 
    context = factory.create_context(input_data)
    #### Вывод 
    context.SourceData is source_data                                               → True
context.index                                                                   → 5
context.PersonType is AllXMLFields.ERZL.OperationsStr.FindPersonsType.MOSCOW    → True
context.AttemptId                                                               → ATTEMPT_ID_START
context.DataAttemptStr                                                          → ()
context.xml_bytes                                                               → None
context.response_bytes                                                          → None
context.ERZL_id                                                                 → None

PASSED

    Пятый тест: runtime-поля записываются через адаптеры

    Пятый тест показывает нам полный цикл записи runtime-данных в контекст через адаптерный слой. У теста вывод именно такой потому что ERZL_Context принимает обновления только через адаптеры, и каждый адаптер отвечает строго за своё поле: xml_bytes, response_bytes, rslt_container, ERZL_id, create_flags.

    Показать вызовСкрыть вызов
    #### Вход 
    context         = ERZL_Context(SourceData={PersonFields.SURNAME: 'Ivanov'}, index=1, ...)
selector_result = TupleDataSelectorRslt(selected_columns=(PersonFields.SURNAME,))
parsed_result   = XMLRsltContainer(
    result=[
        XMLFieldValDTO(
            response_name='findPersonsResponse',
            container=[XMLOneFieldVal(container_name='ERZL_ID', container_val='ERZL-42')],
        )
    ],
    mistakes=[
        XMLErrorDTO(
            response_name='findPersonsResponse',
            container=[XMLErrorVal(error_code='W01', error_val='warning')],
        )
    ],
)
    #### Вызов 
    column_adapter.input_DataSelectorRslt(context, selector_result)
bytes_adapter.put_bytes(context, b"<xml />")
transport_adapter.answer_bytes_to_ctx(
    TransportResponseDTO(output_bytes=b"<response />", status_code=200),
    context,
)
answer_adapter.rslt_container_to_ctx(context, parsed_result)
erzl_adapter.set_ERZL_id(context, "ERZL-42")
erzl_adapter.set_need_create(context)
erzl_adapter.set_good_create_base(context)
    #### Вывод 
    context.DataAttemptStr              == (PersonFields.SURNAME,) → True
context.xml_bytes                   == b"<xml />"              → True
context.response_bytes              == b"<response />"         → True
context.rslt_container.result       == parsed_result.result    → True
context.rslt_container.mistakes     == parsed_result.mistakes  → True
context.ERZL_id                     == "ERZL-42"               → True
context.create_flags.need_create    is True                    → True
context.create_flags.good_create_base is True                  → True

PASSED
