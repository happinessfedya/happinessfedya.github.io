    Тесты ERZL_Context

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/source/test_erzl_context.py

    Флаг -s здесь оставлен для единообразия. Тесты не печатают собственных сценарных блоков, поэтому в консоли видны только имена тестов и статусы PASSED. Ниже раскрыто, какое состояние ERZL_Context проверяет каждый тест.

    Докстринг модуля

    Контрактные тесты для `Source.source_core_types.ERZL_Context`.

Модуль проверяет состав полей `ERZL_Context`, стартовые runtime-значения,
независимость default-factory объектов и корректность обновления контекста
через адаптерный слой.

Тесты нужны для защиты контракта базового context-DTO, который проходит через
pipeline, adapters и XML-взаимодействие.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    ERZL_Context — это основной runtime-контекст одной персоны в ERZL-пайплайне. Его создает ERZLContextFactory, а затем его поэтапно наполняют Source-, Adapter-, XML- и Pipeline-шаги.

    Этот context:

    • хранит нормализованные SourceData и индекс строки;
    • держит текущую search/create runtime-информацию;
    • накапливает xml_bytes, response_bytes, rslt_container, ERZL_id и create_flags.

    Этот context не:

    • не принимает orchestration-решения сам;
    • не строит XML и не парсит ответ собственными методами;
    • не должен делить mutable-состояние между разными экземплярами.

    Первый тест: ожидаемые поля и стартовые значения

    Докстринг теста

    Проверяет состав полей `ERZL_Context` и его стартовое runtime-состояние.

    Первый тест защищает одновременно shape и начальное состояние контекста. Он проверяет не только имена полей, но и то, какие значения должны стоять в DataAttemptStr, xml_bytes, response_bytes, rslt_container, ERZL_id и create_flags сразу после создания.

    Это важно, потому что все следующие шаги пайплайна рассчитывают именно на такую стартовую конфигурацию.

        "index",
        "PersonType",

        "DataAttemptStr",

    assert context.response_bytes is None
    assert context.rslt_container.result == []
    assert context.rslt_container.mistakes == []

    Третий тест: default_factory объекты независимы между context-ами

    Докстринг теста

    Проверяет независимость default-factory объектов между экземплярами context.

    Третий тест показывает, что rslt_container и create_flags должны создаваться заново для каждого экземпляра контекста. Иначе состояние одной персоны просачивалось бы в другую.

    Поэтому после модификации left_context отдельно проверяется, что right_context остался в стартовом состоянии.

    Показать код тестаСкрыть код теста 
    def test_erzl_context_default_factories_are_independent_between_instances() -> None:
    """Проверяет независимость default-factory объектов между экземплярами context."""
    # Arrange
    left_context = _make_context()
    right_context = _make_context()

    # Act
    left_context.rslt_container.result.append(
        XMLFieldValDTO(
            response_name="findPersonsResponse",
            container=[XMLOneFieldVal(container_name="erzlId", container_val="123")],
        )
    )
    left_context.create_flags.need_create = True

    # Assert
    assert left_context.rslt_container is not right_context.rslt_container
    assert left_context.create_flags is not right_context.create_flags
    assert len(left_context.rslt_container.result) == 1
    assert right_context.rslt_container.result == []
    assert left_context.create_flags.need_create is True
    assert right_context.create_flags.need_create is False

    Пятый тест: runtime-поля заполняются через адаптерный слой

    Докстринг теста

    Проверяет обновление runtime-полей `ERZL_Context` через адаптерный слой.

    Последний тест показывает архитектурную роль context в живой цепочке записей. ERZL_Context сам ничего не обновляет, но его runtime-поля последовательно заполняются через ColumnSelectorAdapter, AdapterPutBytes, TransportAdapter, GetXMLAnswerAdapter и ERZLAdapter.

    Это важно, потому что тест защищает не только поля DTO, но и сам принцип: изменения context происходят через отдельные специализированные адаптеры.

    Показать код тестаСкрыть код теста 
    def test_erzl_context_runtime_fields_are_written_through_adapters() -> None:
    """Проверяет обновление runtime-полей `ERZL_Context` через адаптерный слой."""
    # Arrange
    context = _make_context()
    column_adapter = ColumnSelectorAdapter[PersonFields]()
    bytes_adapter = AdapterPutBytes()
    transport_adapter = TransportAdapter()
    answer_adapter = GetXMLAnswerAdapter()
    erzl_adapter = ERZLAdapter()
    selector_result = TupleDataSelectorRslt(
        selected_columns=(PersonFields.SURNAME,)
    )
    parsed_result = XMLRsltContainer(
        result=[
            XMLFieldValDTO(
                response_name="findPersonsResponse",
                container=[
                    XMLOneFieldVal(container_name="ERZL_ID", container_val="ERZL-42")
                ],
            )
        ],
        mistakes=[
            XMLErrorDTO(
                response_name="findPersonsResponse",
                container=[XMLErrorVal(error_code="W01", error_val="warning")],
            )
        ],
    )

    # Act
    column_adapter.input_DataSelectorRslt(context, selector_result)
    bytes_adapter.put_bytes(context, b"<xml />")
    transport_adapter.answer_bytes_to_ctx(
        TransportResponseDTO(output_bytes=b"<response />", status_code=200),
        context,
    )
    answer_adapter.rslt_container_to_ctx(context, parsed_result)
    erzl_adapter.set_ERZL_id(context, "ERZL-42")
    erzl_adapter.set_need_create(context)
    erzl_adapter.set_good_create_base(context)

    # Assert
    assert context.DataAttemptStr == (PersonFields.SURNAME,)
    assert context.xml_bytes == b"<xml />"
    assert context.response_bytes == b"<response />"
    assert context.rslt_container.result == parsed_result.result
    assert context.rslt_container.mistakes == parsed_result.mistakes
    assert context.ERZL_id == "ERZL-42"
    assert context.create_flags.need_create is True
    assert context.create_flags.good_create_base is True
