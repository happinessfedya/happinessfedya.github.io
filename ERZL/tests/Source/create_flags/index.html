    Тесты CreateFlags

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/source/test_create_flags.py

    Флаг -s здесь оставлен для единообразия. Этот модуль сам ничего не печатает, поэтому в консоли видны только имена тестов и статусы PASSED. Ниже раскрывается, какое именно состояние DTO проверяет каждый тест.

    Докстринг модуля

    Контрактные тесты для `Source.source_core_types.CreateFlags`.

Модуль проверяет стартовое состояние `CreateFlags`, независимость его полей,
строгость slotted-поверхности и характер `CreateFlags` как простого DTO без
вшитых бизнес-ограничений.

Тесты нужны для защиты контракта флагов create-flow и для проверки их
корректной интеграции с `ERZL_Context` и `ERZLAdapter`.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    CreateFlags живет в Source-слое как маленький slotted DTO для состояния create-flow. Он входит в ERZL_Context, хранит только булевы флаги и не принимает бизнес-решения сам по себе.

    Этот класс:

    • хранит факт необходимости создания и отдельные признаки успеха по шагам;
    • создается с безопасными значениями по умолчанию;
    • может заменяться адаптером целиком при сбросе состояния.

    Этот класс не:

    • валидирует логическую согласованность комбинаций флагов;
    • не знает про retry, orchestrator или XML;
    • не скрывает ошибки через собственные методы, потому что методов у него нет.

    Докстринг теста

    Проверяет, что `CreateFlags` стартует со всеми выключенными флагами.

    Второй тест: независимое переключение полей

    Докстринг теста

    Проверяет независимое переключение каждого поля `CreateFlags`.

    Второй тест показывает, что каждое поле в CreateFlags существует как отдельный бит состояния. Включение одного признака не должно автоматически включать соседние поля.

    Именно поэтому в цикле поочередно выставляется True для каждого имени поля, а затем проверяется, что остальные остаются False.

    Показать код тестаСкрыть код теста 
    def test_create_flags_fields_can_toggle_independently() -> None:
    """Проверяет независимое переключение каждого поля `CreateFlags`."""
    # Arrange
    flags = CreateFlags()
    field_names = (
        "need_create",
        "good_create_base",
        "good_create_policy",
        "good_create_DUDL",
        "good_create_address",
    )

    # Act / Assert
    for field_name in field_names:
        setattr(flags, field_name, True)

        assert getattr(flags, field_name) is True
        assert all(
            getattr(flags, other_name) is False
            for other_name in field_names
            if other_name != field_name
        )

        setattr(flags, field_name, False)
        assert all(getattr(flags, name) is False for name in field_names)

    Четвертый тест: DTO не валидирует бизнес-логику

    Докстринг теста

    Проверяет, что `CreateFlags` хранит сырой state без бизнес-валидации.

    Четвертый тест показывает принципиальную границу ответственности класса. CreateFlags хранит состояние как есть и не пытается оценивать, логична ли комбинация флагов с точки зрения create-flow.

    Поэтому состояние good_create_base=True при need_create=False считается допустимым для самого DTO, даже если такая комбинация потом может требовать отдельной обработки в другом слое.

    Шестой тест: у каждого context свой экземпляр CreateFlags

    Докстринг теста

    Проверяет отдельный экземпляр `CreateFlags` для каждого `ERZL_Context`.

    Шестой тест уже смотрит не на сам DTO, а на его использование внутри ERZL_Context. Он проверяет, что default_factory выдает разные объекты, а не один общий экземпляр на все контексты.

    Поэтому изменение флага у left_context не должно просачиваться в right_context.

    Показать код тестаСкрыть код теста 
    def test_erzl_context_gets_independent_create_flags_instances() -> None:
    """Проверяет отдельный экземпляр `CreateFlags` для каждого `ERZL_Context`."""
    # Arrange
    left_context = _make_context()
    right_context = _make_context()

    # Act
    left_context.create_flags.need_create = True

    # Assert
    assert left_context.create_flags is not right_context.create_flags
    assert left_context.create_flags.need_create is True
    assert right_context.create_flags.need_create is False

    Седьмой тест: reset заменяет старый DTO новым дефолтным состоянием

    Докстринг теста

    Проверяет сброс флагов на новый DTO с дефолтным состоянием.

    Последний тест показывает реальное место использования CreateFlags: ERZLAdapter.reset_create_flags(context) не обнуляет поля по одному, а подменяет context.create_flags новым экземпляром.

    Именно поэтому после сброса проверяются сразу две вещи: ссылка на объект изменилась и новое состояние полностью совпало с CreateFlags().
