    Тесты CreateFlags

    Эта страница показывает contract-тесты для CreateFlags как документацию контракта. В браузере Python не запускается: блоки Показать вызов раскрывают сценарий и ожидаемое поведение, которое проверяет команда:

    python -m pytest -vv -s tests/source/test_create_flags.py

    Флаг -s нужен, чтобы pytest не скрывал вывод успешно прошедших тестов.

    Зачем этот DTO

    CreateFlags стоит внутри ERZL_Context на слое Source. Он хранит булевые флаги, которые управляют create-flow пайплайна: нужно ли создавать персону, и прошли ли отдельные шаги создания.

    CreateFlags создаётся автоматически при инициализации ERZL_Context:

    context.create_flags  # → CreateFlags()

    Первый тест: значения по умолчанию

    Первый тест показывает нам стартовое состояние DTO: при создании CreateFlags() без аргументов все пять флагов равны False. У теста вывод именно такой потому что каждое поле объявлено с default=False, и create-flow считается выключенным до первого явного включения.

    Показать вызовСкрыть вызов
    #### Вход 
    flags = CreateFlags()
    #### Вызов 
    assert flags.need_create is False
assert flags.good_create_base is False
assert flags.good_create_policy is False
assert flags.good_create_DUDL is False
assert flags.good_create_address is False
    #### Вывод 
    PASSED

    Второй тест: независимое переключение флагов

    Второй тест показывает нам, что каждое поле можно включить и выключить по отдельности, не затрагивая соседние. У теста вывод именно такой потому что поля CreateFlags — независимые атрибуты dataclass без взаимных ограничений; изменение одного не влечёт сайд-эффектов для остальных.

    Показать вызовСкрыть вызов
    #### Вход 
    flags = CreateFlags()
field_names = (
    "need_create",
    "good_create_base",
    "good_create_policy",
    "good_create_DUDL",
    "good_create_address",
)
    #### Вызов 
    for field_name in field_names:
    setattr(flags, field_name, True)   # только это поле True
    setattr(flags, field_name, False)  # снова все False
    #### Вывод 
    PASSED

    Третий тест: слоты запрещают неизвестные атрибуты

    Третий тест показывает нам защиту @dataclass(slots=True): попытка назначить атрибут, которого нет в определении класса, немедленно поднимает AttributeError. У теста вывод именно такой потому что __slots__ не включает имя good_create_unknown, и Python отказывает в создании этого атрибута.

    Показать вызовСкрыть вызов
    #### Вход 
    flags = CreateFlags()
    #### Вызов 
    flags.good_create_unknown = True
    #### Ошибка 
    AttributeError: 'CreateFlags' object has no attribute 'good_create_unknown'

PASSED

    Четвёртый тест: частичное и логически несогласованное состояние

    Четвёртый тест показывает нам, что CreateFlags — чистый DTO без бизнес-валидации: можно установить good_create_base = True при need_create = False, и никакого исключения не будет. У теста вывод именно такой потому что проверка согласованности флагов — ответственность Orchestrator, а не DTO.

    Показать вызовСкрыть вызов
    #### Вход 
    flags = CreateFlags()
    #### Вызов 
    flags.good_create_base = True
flags.need_create = False
    #### Вывод 
    flags.good_create_base    is True   → True
flags.need_create         is False  → True
flags.good_create_policy  is False  → True
flags.good_create_DUDL    is False  → True
flags.good_create_address is False  → True

PASSED

    Пятый тест: контракт полей DTO зафиксирован

    Пятый тест показывает нам, что CreateFlags содержит ровно пять булевых полей с точными именами и порядком объявления. У теста вывод именно такой потому что dataclasses.fields() и get_type_hints() фиксируют публичный контракт DTO, и тест не позволит добавить или переименовать поле без явного обновления этой фиксации.

    Показать вызовСкрыть вызов
    #### Вход 
    dto_fields = fields(CreateFlags)
type_hints = get_type_hints(CreateFlags)
    #### Вызов 
    field_names = tuple(field.name for field in dto_fields)
    #### Вывод 
    field_names == (
    'need_create',
    'good_create_base',
    'good_create_policy',
    'good_create_DUDL',
    'good_create_address',
)
all(type_hints[name] is bool for name in field_names) → True

PASSED

    Шестой тест: независимые экземпляры CreateFlags у контекстов

    Шестой тест показывает нам, что каждый ERZL_Context получает собственный независимый объект CreateFlags через default_factory. У теста вывод именно такой потому что если бы контексты разделяли один объект, изменение left_context.create_flags.need_create повлияло бы и на right_context.

    Показать вызовСкрыть вызов
    #### Вход 
    left_context  = ERZL_Context(SourceData={PersonFields.SURNAME: 'Ivanov'}, index=0, ...)
right_context = ERZL_Context(SourceData={PersonFields.SURNAME: 'Ivanov'}, index=0, ...)
    #### Вызов 
    left_context.create_flags.need_create = True
    #### Вывод 
    left_context.create_flags is not right_context.create_flags → True
left_context.create_flags.need_create                       → True
right_context.create_flags.need_create                      → False

PASSED

    Седьмой тест: reset_create_flags заменяет объект целиком

    Седьмой тест показывает нам, что ERZLAdapter.reset_create_flags() не обнуляет поля по одному, а полностью заменяет context.create_flags на новый CreateFlags(). У теста вывод именно такой потому что после вызова идентичность объекта меняется (context.create_flags is not old_flags), а значения совпадают с дефолтными.

    Показать вызовСкрыть вызов
    #### Вход 
    adapter = ERZLAdapter()
context = ERZL_Context(SourceData={PersonFields.SURNAME: 'Ivanov'}, index=0, ...)
context.create_flags.need_create      = True
context.create_flags.good_create_base = True
old_flags = context.create_flags
    #### Вызов 
    adapter.reset_create_flags(context)
    #### Вывод 
    context.create_flags is not old_flags → True
context.create_flags == CreateFlags() → True

PASSED
