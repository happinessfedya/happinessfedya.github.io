    Тесты XLSMRowDTO

    Эта страница показывает contract-тесты для XLSMRowDTO как документацию контракта. В браузере Python не запускается: блоки Показать вызов раскрывают сценарий и ожидаемое поведение, которое проверяет команда:

    python -m pytest -vv -s tests/source/test_xlsm_row_dto.py

    Флаг -s нужен, чтобы pytest не скрывал вывод успешно прошедших тестов.

    Зачем этот DTO

    XLSMRowDTO стоит на выходе слоя Source. SourceData.run_getData() читает XLSM-файл и возвращает объекты XLSMRowDTO — по одному на строку. Адаптер RenameToSourceInputAdapter принимает XLSMRowDTO и конвертирует его в SourceInput для слоя Adapters.

    dto = XLSMRowDTO(data={"\u0424\u0430\u043c\u0438\u043b\u0438\u044f": "\u0418\u0432\u0430\u043d\u043e\u0432", ...}, index=5)
dto.data   # → {"\u0424\u0430\u043c\u0438\u043b\u0438\u044f": "\u0418\u0432\u0430\u043d\u043e\u0432", ...}
dto.index  # → 5

    Первый тест: сохранение данных источника и индекса

    Первый тест показывает нам, что XLSMRowDTO хранит тот же объект словаря и тот же индекс строки, которые были переданы при создании. У теста вывод именно такой потому что data — это ссылка на переданный словарь (dto.data is source_data), а не копия; index — простое целочисленное поле.

    Показать вызовСкрыть вызов
    #### Вход 
    source_data = {
    'Surname':       'Ivanov',
    'IndexInt':      7,
    'FloatValue':    1.5,
    'BoolValue':     True,
    'DateValue':     date(1990, 1, 20),
    'DateTimeValue': datetime(2026, 5, 14, 10, 30),
    'TimeValue':     time(8, 45),
    'DeltaValue':    timedelta(days=2, minutes=5),
    'EmptyCell':     None,
}
    #### Вызов 
    dto = XLSMRowDTO(data=source_data, index=2)
    #### Вывод 
    dto.data is source_data → True
dto.data == source_data → True
dto.index               → 2

PASSED

    Второй тест: пустые данные и граничный индекс

    Второй тест показывает нам, что XLSMRowDTO не валидирует данные — пустой словарь и индекс 0 принимаются без ошибок. У теста вывод именно такой потому что DTO — тупой контейнер; проверка корректности строк — ответственность слоя Source.

    Показать вызовСкрыть вызов
    #### Вход 
    source_data = {}
    #### Вызов 
    dto = XLSMRowDTO(data=source_data, index=0)
    #### Вывод 
    dto.data  == {} → True
dto.index       → 0

PASSED

    Третий тест: frozen запрещает переназначение полей

    Третий тест показывает нам, что @dataclass(frozen=True) блокирует попытку переназначить поля index и data. У теста вывод именно такой потому что frozen=True генерирует __setattr__ и __delattr__, которые всегда поднимают FrozenInstanceError.

    Показать вызовСкрыть вызов
    #### Вход 
    dto = XLSMRowDTO(data={"Surname": "Ivanov"}, index=1)
    #### Вызов 
    dto.index = 3
dto.data  = {"Surname": "Petrov"}
    #### Ошибка 
    FrozenInstanceError: cannot assign to field 'index'
FrozenInstanceError: cannot assign to field 'data'

PASSED

    Четвёртый тест: вложенный словарь остаётся изменяемым

    Четвёртый тест показывает нам, что frozen=True защищает только привязку атрибутов DTO, но не делает вложенный словарь иммутабельным. У теста вывод именно такой потому что dto.data — это обычный dict, и frozen не рекурсивно замораживает его содержимое.

    Показать вызовСкрыть вызов
    #### Вход 
    dto = XLSMRowDTO(data={"Surname": "Ivanov"}, index=4)
    #### Вызов 
    dto.data["GivenName"] = "Ivan"
    #### Вывод 
    dto.data == {"Surname": "Ivanov", "GivenName": "Ivan"} → True

PASSED

    Пятый тест: строковые ключи источника и только два поля

    Пятый тест показывает нам, что XLSMRowDTO хранит только два поля (data и index), а словарь данных типизирован как dict[str, SourceValue]. У теста вывод именно такой потому что сырые имена колонок XLSM — это строки, и DTO специально не использует PersonFields для ключей, чтобы не смешивать слои.

    Показать вызовСкрыть вызов
    #### Вход 
    dto_fields = fields(XLSMRowDTO)
type_hints = get_type_hints(XLSMRowDTO)
data_hint  = type_hints["data"]
    #### Вызов 
    data_origin          = get_origin(data_hint)
key_type, value_type = get_args(data_hint)
field_names          = tuple(field.name for field in dto_fields)
    #### Вывод 
    field_names == ("data", "index")                          → True
data_origin is dict                                       → True
key_type    is str                                        → True
set(get_args(value_type)) == set(get_args(SourceValue))   → True
type_hints["index"] is int                                → True

PASSED

    Шестой тест: отсутствие адаптерных и XML-терминов в теле класса

    Шестой тест показывает нам, что XLSMRowDTO остаётся чистым source-DTO без прямого знания о downstream-слоях. У теста вывод именно такой потому что наличие символов PersonType, xml_bytes или XMLFields в теле класса означало бы нарушение слоевых границ.

    Показать вызовСкрыть вызов
    #### Вход 
    class_source    = inspect.getsource(XLSMRowDTO)
forbidden_terms = (
    "PersonType",
    "AttemptId",
    "xml_bytes",
    "response_bytes",
    "rslt_container",
    "XMLFields",
    "RenameToSourceInputAdapter",
)
    #### Вызов 
    unexpected_terms = [term for term in forbidden_terms if term in class_source]
    #### Вывод 
    unexpected_terms == [] → True

PASSED
