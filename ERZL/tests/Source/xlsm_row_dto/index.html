    Тесты XLSMRowDTO

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/source/test_xlsm_row_dto.py

    Флаг -s здесь не добавляет пользовательского вывода: тесты не печатают дополнительных строк, поэтому в консоли видны только имена сценариев и статусы PASSED. Ниже раскрыто, какое именно состояние DTO фиксирует каждый тест.

    Докстринг модуля

    Контрактные тесты для `Source.source_core_types.XLSMRowDTO`.

Модуль проверяет структуру `XLSMRowDTO`, сохранение исходного payload,
поведение frozen-датакласса, типовой контракт полей и отсутствие примесей
из downstream-слоев.

Тесты нужны для защиты DTO границы source-слоя, который должен хранить сырые
данные строки XLSM без доменной или XML-специфичной логики.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    XLSMRowDTO — это замороженный DTO одной строки источника. Он находится на самой границе Source-слоя и хранит ровно две вещи: сырой словарь значений ячеек и индекс строки.

    Этот DTO:

    • упаковывает строку XLSM в типизированную форму;
    • сохраняет исходный payload без доменной нормализации;
    • переносит индекс строки дальше по пайплайну.

    Этот DTO не:

    • не переименовывает поля;
    • не валидирует бизнес-смысл значений;
    • не знает ничего о PersonFields, XML и context-слое.

    Первый тест: payload и index сохраняются как есть

    Докстринг теста

    Проверяет сохранение исходного payload и индекса строки.

    Первый тест показывает главный контракт DTO: входной словарь не копируется и не пересобирается, а индекс строки просто сохраняется рядом с ним.

    У теста вывод именно такой потому что XLSMRowDTO должен оставаться простым контейнером source-данных, а не слоем преобразования.

    Второй тест: пустой словарь и нулевой index допустимы

    Докстринг теста

    Проверяет, что валидация пустых данных и граничного индекса не встроена в DTO.

    Второй тест показывает, что XLSMRowDTO не берет на себя лишнюю валидацию. Пустой data={} и index=0 считаются допустимым runtime-состоянием самого DTO.

    Это важно, потому что решение о том, валидна ли строка источника, должно оставаться в Source-логике, а не в контейнере данных.

    Третий тест: frozen запрещает переназначение атрибутов

    Докстринг теста

    Проверяет запрет переназначения атрибутов благодаря `frozen=True`.

    Третий тест защищает immutability-контракт самого объекта. После создания нельзя переприсвоить dto.index или весь dto.data целиком.

    Это не делает вложенный словарь неизменяемым, но защищает верхний слой DTO от случайной подмены атрибутов.

    Показать код тестаСкрыть код теста 
    def test_xlsm_row_dto_is_frozen_for_attribute_reassignment() -> None:

    # Arrange
    dto = XLSMRowDTO(data={"Surname": "Ivanov"}, index=1)

    with pytest.raises(FrozenInstanceError):
        dto.index = 3

    with pytest.raises(FrozenInstanceError):
        dto.data = {"Surname": "Petrov"}

    Четвертый тест: вложенный словарь остается изменяемым

    Докстринг теста

    Проверяет, что вложенный словарь данных остается изменяемым.

    Четвертый тест специально показывает, что frozen=True не превращает вложенный dict в immutable-структуру. Сам DTO заморожен, но объект словаря внутри него остается обычным изменяемым словарем.

    У теста вывод именно такой потому что это явная часть контракта текущей модели данных, а не побочный эффект.

    Пятый тест: контракт полей остается минимальным

    Докстринг теста

    Проверяет сырой строковый ключ данных и минимальный контракт полей DTO.

    Пятый тест защищает форму DTO через fields() и type_hints. Он проверяет, что у класса по-прежнему только два поля, что data использует строковые ключи и что тип значений совпадает с union SourceValue.

    Это важно, потому что DTO должен оставаться универсальной упаковкой строки источника, а не превращаться в доменно-нормализованную структуру.

    def test_xlsm_row_dto_uses_raw_source_string_keys_and_only_two_fields() -> None:
    """Проверяет сырой строковый ключ данных и минимальный контракт полей DTO."""
    # Arrange
    dto_fields = fields(XLSMRowDTO)
    type_hints = get_type_hints(XLSMRowDTO)
    data_hint = type_hints["data"]

    # Act
    data_origin = get_origin(data_hint)
    key_type, value_type = get_args(data_hint)
    field_names = tuple(field.name for field in dto_fields)

    # Assert

    assert data_origin is dict
    assert key_type is str
    assert set(get_args(value_type)) == set(get_args(SourceValue))

    Шестой тест: в DTO нет adapter- и XML-терминов

    Докстринг теста

    Проверяет, что `XLSMRowDTO` не встраивает adapter- или XML-логику.

    Последний тест защищает архитектурную чистоту Source-слоя. В теле XLSMRowDTO не должно быть терминов вроде PersonType, xml_bytes или RenameToSourceInputAdapter.

    Именно поэтому анализируется исходный код класса, а не только его поля и значения после создания экземпляра.

    Показать код тестаСкрыть код теста 
    def test_xlsm_row_dto_class_body_does_not_embed_adapter_or_xml_terms() -> None:
