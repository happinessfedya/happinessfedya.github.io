    Тесты PersonFields

    Эта страница показывает contract-тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/source/test_person_fields.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит дополнительные строки, поэтому в консоли видны только имена тестов и статусы PASSED. Ниже раскрывается, какие свойства enum на самом деле защищают эти проверки.

    Докстринг модуля

    Контрактные тесты для `Source.source_core_types.PersonFields`.

Модуль проверяет состав значений `PersonFields`, поведение enum как строкового
типа, уникальность и корректность его alias-значений, а также отсутствие
зависимости от XML-слоя.

Тесты нужны для защиты контракта source-уровня, где `PersonFields` должен
оставаться стабильным перечислением канонических полей источника.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    PersonFields — это канонический enum Source-слоя. Он задает стабильные имена полей персоны, которыми уже оперируют адаптеры, контекст и селектор попыток.

    Этот enum:

    • дает единый набор canonical alias-значений;
    • ведет себя как строковый тип, поэтому подходит для словарей и сериализации;
    • отделяет source-уровень от XML-слоя.

    Этот enum не:

    • не хранит XML-ключи и XML-маппинг;
    • не знает про транспорт, orchestrator и runtime-контекст;
    • не валидирует значения пациента, он описывает только имена полей.

    Первый тест: стабильный набор alias-значений

    Докстринг теста

    Проверяет стабильный набор канонических alias-значений `PersonFields`.

    Первый тест защищает самый важный внешний контракт enum: точный набор имен и строковых значений. Если одно из них незаметно изменится, downstream-слои перестанут находить нужные ключи.

    Поэтому тест сравнивает не отдельные элементы, а сразу весь словарь {field.name: field.value}.

    Показать код тестаСкрыть код теста 
    def test_person_fields_exposes_expected_canonical_values() -> None:
    """Проверяет стабильный набор канонических alias-значений `PersonFields`."""
    # Arrange
    expected_values = {
        "SURNAME": "surname",
        "NAME": "namep",
        "SEX_ID": "sexId",
        "CITIZEN_CODE": "citizenship",
        "SNILS": "snils",
        "DATE_BIRTH": "dateBirth",
        "PATRONYMIC": "patronymic",
        "POLICY_TYPE": "policyT",
        "INSURP_ID": "insurpId",
        "POLICY_STATUS": "sPolicyStatusCode",
        "POLICY_OKATO_ID": "policy_okatoId",
        "POLICY_DATE_BEGIN": "policyDateB",
        "DUDL_TYPE": "dudlTypeId",
        "OKSM_ID": "countryDudl",
        "DUDL_SERIES": "dudlSer",
        "DUDL_NUMBER": "dudlNom",
        "ADDRESS_TYPE": "adrTypeId",
        "ADDRESS_OKATO_ID": "address_okatoId",
    }

    # Act
    actual_values = {field.name: field.value for field in PersonFields}

    # Assert
    assert actual_values == expected_values

    #### Вызов

    Второй тест: enum ведет себя как str

    Докстринг теста

    Проверяет строковое поведение enum и восстановление по значению.

    Второй тест показывает две стороны одного контракта: элемент enum должен нормально представляться как строка и должен восстанавливаться по своему alias-значению.

    Это важно, потому что PersonFields используется и как enum в Python-коде, и как строковый ключ в словарях и преобразованиях.

    Показать код тестаСкрыть код теста 
    def test_person_fields_behaves_as_str_enum() -> None:
    """Проверяет строковое поведение enum и восстановление по значению."""
    # Arrange
    field = PersonFields.SURNAME

    # Act
    field_as_str = str(field)
    restored_field = PersonFields("surname")

    # Assert
    assert field_as_str == "surname"
    assert restored_field is PersonFields.SURNAME
    Показать вызовСкрыть вызов
    #### Вход 
    field = PersonFields.SURNAME
    #### Вызов 
    field_as_str = str(field)
restored_field = PersonFields("surname")
    #### Вывод 
    Тест ничего не печатает.

restored_field is PersonFields.SURNAME

    Третий тест: значения уникальны, непусты и без лишних пробелов

    Докстринг теста

    Проверяет уникальность, непустоту и отсутствие лишних пробелов в значениях.

    Третий тест защищает качество самих alias-значений. Он нужен не для бизнес-логики, а для того, чтобы перечисление не разъехалось дубликатами, пустыми строками и случайными пробелами.

    У теста вывод именно такой, потому что все проверки делаются на полном списке [field.value for field in PersonFields], а не на одном выбранном элементе.

    Показать код тестаСкрыть код теста 
    def test_person_fields_values_are_unique_non_empty_and_trimmed() -> None:
    """Проверяет уникальность, непустоту и отсутствие лишних пробелов в значениях."""
    # Arrange
    values = [field.value for field in PersonFields]

    # Act
    unique_values = set(values)

    # Assert
    assert len(unique_values) == len(PersonFields)
    assert all(value != "" for value in values)
    assert all(value == value.strip() for value in values)
    Показать вызовСкрыть вызов
    #### Вход 
    values = [field.value for field in PersonFields]
    #### Вызов 
    unique_values = set(values)
    #### Вывод 
    Тест ничего не печатает.
Проверяются инварианты:
len(unique_values) == len(PersonFields)
в values нет ""
для каждого value выполняется value == value.strip()

    Четвертый тест: неизвестное значение отвергается

    Докстринг теста

    Проверяет отклонение неизвестного alias-значения.

    Четвертый тест фиксирует отрицательный сценарий: enum должен восстанавливаться только по известным строкам, а произвольный alias "unknown" обязан завершаться ошибкой.

    Это защищает код, который строит PersonFields из внешних значений и должен быстро замечать некорректный alias вместо тихой подстановки.

    Показать код тестаСкрыть код теста 
    def test_person_fields_rejects_unknown_value() -> None:
    """Проверяет отклонение неизвестного alias-значения."""
    # Arrange
    invalid_value = "unknown"

    # Act / Assert
    with pytest.raises(ValueError):
        PersonFields(invalid_value)
    Показать вызовСкрыть вызов
    #### Вход 
    invalid_value = "unknown"
    #### Вызов 
    with pytest.raises(ValueError):
    PersonFields(invalid_value)
    #### Ошибка 
    Тест ничего не печатает.
Проверяется только тип исключения: ValueError.
Текст ошибки тестом не фиксируется.

    Пятый тест: в теле enum нет XML-логики

    Докстринг теста

    Проверяет, что `PersonFields` не встраивает в себя XML-логику.

    Последний тест смотрит не на значения enum, а на архитектурную границу слоя. PersonFields не должен зависеть от XMLFields, XMLKVPairs или XML_FIELDS_RENAME.

    Именно поэтому берется исходный код класса через inspect.getsource, а затем проверяется отсутствие запрещенных терминов.

    Показать код тестаСкрыть код теста 
    def test_person_fields_class_body_does_not_embed_xml_mapping_terms() -> None:
    """Проверяет, что `PersonFields` не встраивает в себя XML-логику."""
    # Arrange
    class_source = inspect.getsource(PersonFields)
    forbidden_terms = ("XMLFields", "XMLKVPairs", "XML_FIELDS_RENAME")

    # Act
    unexpected_terms = [term for term in forbidden_terms if term in class_source]

    # Assert
    assert unexpected_terms == []
    Показать вызовСкрыть вызов
    #### Вход

forbidden_terms = ("XMLFields", "XMLKVPairs", "XML_FIELDS_RENAME")
    #### Вызов 
    unexpected_terms = [term for term in forbidden_terms if term in class_source]
    #### Вывод 
    Тест ничего не печатает.
Проверяется состояние:
unexpected_terms == []
