    Тесты PrepareAttemptStep

    Эта страница показывает тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/pipeline/test_prepare_attempt_step.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит свои сценарии, поэтому в pytest видны только имена тестов и статусы PASSED. Ниже раскрыто, какие именно ветки CONTINUE / NEXT_ATTEMPT / NO_MORE_ATTEMPTS, какие ошибки и какие архитектурные ограничения стоят за этими статусами.

    Докстринг модуля

    Тесты для `PrepareAttemptStep`.

Модуль фиксирует контракт шага выбора ключей текущей попытки: работу с
`PrepareAttemptStepCfg`, controlled-ветки `CONTINUE / NEXT_ATTEMPT /
NO_MORE_ATTEMPTS`, а также архитектурную изоляцию от XML- и transport-слоёв.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    PrepareAttemptStep живет в Pipeline-слое и отвечает за подготовку данных текущей search-попытки. Он связывает три зависимости:

    • cfg.attempt_fields хранит упорядоченные наборы полей для каждой попытки;
    • data_selector.make_ColumnsAttemptStr(SourceData, selected_fields) выбирает пригодные поля из source-данных;
    • data_selector_adapter.input_DataSelectorRslt(ctx, rslt) записывает результат selector-а в context.DataAttemptStr.

    Этот шаг:

    • читает AttemptId и SourceData из context;
    • решает, закончились ли попытки;
    • для текущей попытки запрашивает selector;
    • на успехе пишет DataAttemptStr в context;
    • controlled error DataSelectorNoMatchError превращает в NEXT_ATTEMPT.

    Этот шаг не:

    • не строит XML и не работает с xml_bytes;
    • не знает ничего о transport-ответах;
    • не загружает source сам и не обрабатывает NoValidRowsError;
    • не скрывает неожиданные runtime-ошибки collaborators.
