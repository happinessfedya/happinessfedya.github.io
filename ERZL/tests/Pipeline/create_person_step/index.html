    Тесты CreatePersonStep

    Эта страница показывает тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/pipeline/test_create_person_step.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит свои сценарии, поэтому в pytest видны только имена тестов и статусы PASSED. Ниже раскрыто, как именно проверяются обе create-ветки шага, controlled error-сценарии и архитектурные ограничения CreatePersonStep.

    Докстринг модуля

    Тесты для `CreatePersonStep`.

Модуль фиксирует контракт двух create-веток шага: `create_person_base` и
`create_person_not_base`, различие в работе с `ERZL_id`, controlled error-ветки
через `StepRslt.error`, а также архитектурную изоляцию от search- и
transport-логики.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    CreatePersonStep живет в Pipeline-слое и отвечает за подготовку XML для create-flow. У него две публичные ветки:

    • create_person_base(context) для первого create-запроса, где ERZL_id еще нет;
    • create_person_not_base(context, op) для следующих операций, где ERZL_id уже должен быть в context.

    Этот шаг связывает четыре зависимости:

    • data_selector.get_keys_for_xml(...) выбирает required и optional поля для конкретной create-операции;
    • adapter.build_from_source_fields(...) превращает выбранные поля в XMLKVPairs;
    • builder.build_xml(dto) строит XML по XMLCreatePersonDTO;
    • adapter_put_bytes.put_bytes(context, xml_bytes) записывает готовые байты в context.xml_bytes.

    Этот шаг:

    • берет SourceData из context;
    • для base/not-base веток собирает разные DTO;
    • контролирует обязательность ERZL_id только в not-base пути;
    • все ожидаемые error-ветки переводит в StepRslt.error(...).

    Этот шаг не:

    • не работает с search-специфичными AttemptId и DataAttemptStr как с управляющими решениями;
    • не отправляет XML и не читает response_bytes;
    • не скрывает неожиданные runtime-ошибки collaborators;
    • не использует StepRslt.stop(...) для контролируемых create-ошибок.
