    Тесты LoadContextStep

    Эта страница показывает тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/pipeline/test_load_context_step.py

    Флаг -s здесь почти не меняет консольный вывод: модуль не печатает свои сценарии, поэтому в pytest видны только имена тестов и статусы PASSED. Ниже раскрыто, какие именно входы, вызовы и проверяемые результаты стоят за этими статусами.

    Докстринг модуля

    Тесты для `LoadContextStep`.

Модуль проверяет создание контекстов из строк источника, порядок передачи
данных через адаптер и фабрику, обработку ошибок и базовые архитектурные
ограничения шага `LoadContextStep` из `Pipeline.pipeline_protocols`.

Тесты нужны для защиты контракта шага и для контроля, что он остается
предсказуемым при работе как с заглушками, так и с реальными объектами
проекта.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    LoadContextStep живет в Pipeline-слое и отвечает только за раннюю сборку контекста. Он связывает три зависимости:

    • source.run_getData() отдает сырые DTO источника;
    • adapter.adapt(raw_data) превращает их в нормализованный SourceInput;
    • context_builder.create_context(data) создает итоговый runtime-context.

    Этот шаг:

    • итерируется по строкам источника;
    • по одной прогоняет данные через adapter и context factory;
    • yield-ит готовые context-объекты дальше в пайплайн;
    • специально обогащает только NoValidRowsError.

    Этот шаг не:

    • не знает ничего о XML-слое;
    • не принимает orchestration-решения;
    • не мутирует context напрямую после его создания;
    • не скрывает любые ошибки подряд широким except Exception.

    Именно поэтому в rows используются голые object(), а не строки.
