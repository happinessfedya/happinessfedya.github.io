    Тесты BuildSearchXMLStep

    Эта страница показывает тесты из общего test-файла. Команда, на которой основаны сценарии:

    python -m pytest -vv -s tests/pipeline/test_build_search_xml_step.py

    Флаг -s здесь не добавляет пользовательской печати: модуль не выводит свои сценарии, поэтому в pytest видны только имена тестов и статусы PASSED. Ниже раскрыто, какие именно входы, возвраты StepRslt, controlled errors и архитектурные границы стоят за этими статусами.

    Докстринг модуля

    Тесты для `BuildSearchXMLStep`.

Модуль фиксирует контракт шага сборки поискового XML: проброс данных из context
в rename-adapter и builder, различие между STOP и ERROR статусами, а также
архитектурную изоляцию от source- и transport-слоёв.

Тесты нужны для защиты шага, который берет данные текущей попытки из context,
строит поисковый XML через adapter и builder и записывает результат обратно в
context, не смешивая эту логику с source- или transport-ответственностью.

    Исходный код больше не вынесен в один общий блок сверху. Ниже у каждого сценария есть отдельный раскрывающийся блок с кодом именно того теста, который документируется.

    Зачем этот класс

    BuildSearchXMLStep живет в Pipeline-слое и отвечает за сборку поискового XML из уже подготовленных данных текущей попытки. Он связывает три зависимости:

    • adapter_rename.rename_XMLKVPairs_from_ctx(context) берет из context данные попытки и превращает их в XMLKVPairs;
    • builder.build_xml(dto) строит XML-байты по XMLBuilderSearchDTO;
    • adapter_put_bytes.put_bytes(context, xml_bytes) записывает готовый XML обратно в context.xml_bytes.

    Этот шаг:

    • читает PersonType и данные попытки из context;
    • собирает XMLBuilderSearchDTO;
    • различает STOP/ABORT и ERROR/ABORT по типу исключения builder-а;
    • на успешном пути кладет XML-байты в context.

    Этот шаг не:

    • не выбирает данные источника сам;
    • не знает о transport-ответах и response_bytes;
    • не управляет AttemptId и не принимает решения следующей попытки;
    • не скрывает неожиданные runtime-ошибки collaborators.
