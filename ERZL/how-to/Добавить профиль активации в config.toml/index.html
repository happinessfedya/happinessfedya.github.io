    Добавить профиль активации в config.toml

    Порядок действий

    Новый профиль активации в этом проекте задаётся через config/erzl.toml.

    Профиль активации — это набор ссылок в секции:

    [integrations.erzl]

    Именно эта секция определяет, какие блоки source, alias, attempts, XML builder, namespaces, client и transport будут активны при запуске пайплайна.

    Полный порядок такой:

    1. выбрать имя нового профиля;
    2. добавить блок источника;
    3. добавить блок алиасов полей;
    4. добавить блок попыток;
    5. добавить блок XML builder;
    6. добавить блок namespaces;
    7. добавить блок client-данных;
    8. добавить блок client-контейнера;
    9. добавить блок transport;
    10. переключить ссылки в [integrations.erzl] на новый профиль;
    11. проверить, что обязательные ключи профиля совпадают с ожиданиями bootstrap.

    Итоговая схема такая:

    [integrations.erzl]
-> source_ref
-> alias_ref
-> attempts_ref
-> xml_builder_ref
-> xml_namespaces_ref
-> xml_client_cont_ref
-> xml_client_data_ref
-> xml_transport_ref

    1. Выбрать имя профиля

    Файл: config/erzl.toml

    Сначала выберите имя нового профиля. В примере ниже используется имя:

    demo_oms

    Это имя дальше будет использоваться в названиях всех секций:

    • sources.xlsm.demo_oms
    • adapters.erzl.person_fields_alias.demo_oms
    • pipeline_steps.erzl.prepare_attempt_keys.demo_oms
    • xml.erzl.builder.demo_oms
    • xml.erzl.namespaces.demo_oms
    • xml.erzl.builder.client.demo_oms
    • xml.erzl.client_container.demo_oms
    • xml.erzl.transport.demo_oms

    2. Добавить блок источника

    Файл: config/erzl.toml

    Для текущего bootstrap источник должен быть описан как профиль XLSM-источника.

    Изменение

    + [sources.xlsm.demo_oms]
+ XLSMPath = 'W:\Новый профиль\demo_oms.xlsm'
+ SheetName = '05_Пациенты'

    Обязательные ключи

    • XLSMPath
    • SheetName

    3. Добавить блок алиасов полей

    Файл: config/erzl.toml

    В этом блоке задаётся соответствие между колонками источника и каноническими PersonFields.

    Изменение

    + [adapters.erzl.person_fields_alias.demo_oms]
+ surname = ["Пациент Фамилия"]
+ namep = ["Пациент Имя"]
+ sexId = ["Пациент Пол"]
+ citizenship = ["ИД Гражданства ЕРЗЛ"]
+ snils = ["Пациент СНИЛС скорректированный"]
+ dateBirth = ["Пациент Дата рождения"]
+ patronymic = ["Пациент Отчество"]
+ policyT = ["Тип полиса по ЕРЗЛ"]
+ insurpId = ["Код СМО Объед"]
+ sPolicyStatusCode = ["Статус полиса ЕРЗЛ (RefPolicySt)"]
+ policy_okatoId = ["ИД региона полиса"]
+ policyDateB = ["Полис Дата выдачи"]
+ dudlTypeId = ["Тип ДУЛ ЕРЗЛ"]
+ countryDudl = ["ИД Страны выдавшей ДУЛ"]
+ dudlSer = ["Документ Серия"]
+ dudlNom = ["Документ Номер"]
+ adrTypeId = ["Тип Адреса"]
+ address_okatoId = ["Регион Адреса(Address; okatoId)"]

    Что должно быть в этом блоке

    Набор ключей должен покрывать все поля, которые используются:

    • в попытках поиска;
    • в create XML;
    • в XML-маппинге текущего пайплайна.

    4. Добавить блок попыток

    Файл: config/erzl.toml

    Bootstrap текущего проекта ожидает, что в активном профиле попыток будут как минимум ключи:

    • snils_data
    • dudl_fio_data

    Изменение

    + [pipeline_steps.erzl.prepare_attempt_keys.demo_oms]
+ snils_data = ["snils"]
+ dudl_fio_data = ["surname", "namep", "patronymic", "dudlTypeId", "dudlSer", "dudlNom", "countryDudl"]

    Что важно

    Именно эти имена использует config/bootstrap_core_types.py при сборке PrepareAttemptStepCfg.

    5. Добавить блок XML builder

    Файл: config/erzl.toml

    Этот блок задаёт имена XML-prefix для SOAP и service-слоёв.

    Изменение

    + [xml.erzl.builder.demo_oms]
+ soap_prefix = "soapenv"
+ service_prefix = "ser"

    Обязательные ключи

    • soap_prefix
    • service_prefix

    6. Добавить блок namespaces

    Файл: config/erzl.toml

    Bootstrap текущего проекта ожидает, что в активном namespace-профиле будут ключи:

    • soapenv
    • ser

    Изменение

    + [xml.erzl.namespaces.demo_oms]
+ soapenv = "http://schemas.xmlsoap.org/soap/envelope/"
+ ser = "http://erzl.org/services"

    Что важно

    Значения soap_prefix и service_prefix из builder-профиля должны существовать и в namespace-профиле.

    7. Добавить блок client-данных

    Файл: config/erzl.toml

    Этот блок заполняет несекретную часть XML-контейнера client.

    Изменение

    + [xml.erzl.builder.client.demo_oms]
+ org_code = '811'
+ bp_code = '1'
+ system = 'МИС'

    Обязательные ключи в TOML

    • org_code
    • bp_code
    • system

    Секреты вынесены в .env

    Файл: .env

    ERZL_XML_USER=demo_user
ERZL_XML_PASSWORD=demo_password

    Что важно

    config/bootstrap_core_types.py читает логин и пароль не из config/erzl.toml, а из корневого .env. .env должен быть добавлен в .gitignore.

    8. Добавить блок client-контейнера

    Файл: config/erzl.toml

    Этот блок задаёт имя корневого XML-контейнера для client-данных.

    Изменение

    + [xml.erzl.client_container.demo_oms]
+ root_container_name = 'client'

    Обязательные ключи

    • root_container_name

    9. Добавить блок transport

    Файл: config/erzl.toml

    Этот блок задаёт HTTP-параметры отправки XML.

    Изменение

    + [xml.erzl.transport.demo_oms]
+ endpoint = 'http://127.0.0.1:8080/erzlws/policyService'
+ timeout_sec = 30
+ pool_maxsize = 4
+ headers = { "Content-Type" = "text/xml; charset=utf-8" }

    Обязательные ключи

    • endpoint
    • timeout_sec
    • pool_maxsize
    • headers

    10. Переключить активный профиль в [integrations.erzl]

    Файл: config/erzl.toml

    После того как все профильные блоки созданы, нужно переключить ссылки в секции активации.

    Изменение

     [integrations.erzl]
- source_ref = "sources.xlsm.main"
- alias_ref = "adapters.erzl.person_fields_alias.main"
- attempts_ref = "pipeline_steps.erzl.prepare_attempt_keys"
- xml_builder_ref = "xml.erzl.builder.main"
- xml_namespaces_ref = "xml.erzl.namespaces"
- xml_client_cont_ref = 'xml.erzl.client_container.main'
- xml_client_data_ref = 'xml.erzl.builder.client.main'
- xml_transport_ref = 'xml.erzl.transport.main'
+ source_ref = "sources.xlsm.demo_oms"
+ alias_ref = "adapters.erzl.person_fields_alias.demo_oms"
+ attempts_ref = "pipeline_steps.erzl.prepare_attempt_keys.demo_oms"
+ xml_builder_ref = "xml.erzl.builder.demo_oms"
+ xml_namespaces_ref = "xml.erzl.namespaces.demo_oms"
+ xml_client_cont_ref = "xml.erzl.client_container.demo_oms"
+ xml_client_data_ref = "xml.erzl.builder.client.demo_oms"
+ xml_transport_ref = "xml.erzl.transport.demo_oms"

    Что это даст

    После этой правки bootstrap начнёт читать именно новый профиль demo_oms.

    11. Что обязательно проверить после переключения

    Файл проверки логики: config/bootstrap_core_types.py

    Новый профиль будет работать без правок Python-кода, если выполняются все условия:

    1. Источник остаётся XLSM

    Bootstrap сейчас собирает:

    _ERZLMainXLSMSourceCfg = XLSMSourceCfg(...)

    Значит source_ref должен вести в блок вида:

    [sources.xlsm.<профиль>]

    2. В активном attempts-профиле есть оба ключа

    Bootstrap сейчас ожидает:

    attempts_raw["snils_data"]
attempts_raw["dudl_fio_data"]

    Значит в активном профиле попыток должны быть:

    • snils_data
    • dudl_fio_data

    3. В активном namespace-профиле есть оба ключа

    Bootstrap сейчас читает:

    xml_namespaces_raw["soapenv"]
xml_namespaces_raw["ser"]

    Значит в активном namespace-профиле должны быть:

    • soapenv
    • ser

    4. В active client profile есть все обязательные поля

    Bootstrap сейчас читает:

    xml_client_data_raw["org_code"]
xml_client_data_raw["bp_code"]
xml_client_data_raw["system"]
_require_env("ERZL_XML_USER")
_require_env("ERZL_XML_PASSWORD")

    Значит:

    • в xml.erzl.builder.client.<профиль> должны быть заполнены org_code, bp_code, system;
    • в корневом .env должны быть заданы ERZL_XML_USER и ERZL_XML_PASSWORD.

    Готовый результат

    После полной настройки профиль активации должен задаваться только через блок:

    [integrations.erzl]

    Если все ссылки из него указывают на один и тот же профиль, то при старте пайплайн подхватит:

    1. нужный XLSM-источник;
    2. нужные алиасы полей;
    3. нужные search-попытки;
    4. нужные XML builder prefixes;
    5. нужные namespaces;
    6. нужный client-контейнер;
    7. нужный transport.
