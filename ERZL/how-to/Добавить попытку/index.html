    Добавить попытку

    Порядок действий

    Новая попытка в этом проекте добавляется по такой цепочке:

    1. выбрать набор полей для новой попытки;
    2. добавить попытку в конфиг;
    3. подключить попытку в bootstrap;
    4. убедиться, что все поля уже приходят в SourceData;
    5. запустить пайплайн и проверить, что попытка вызывается в нужном порядке.

    Итоговая схема такая:

    config/erzl.toml
-> config/bootstrap_core_types.py
-> PrepareAttemptStepCfg
-> PrepareAttemptStep
-> DataSelector
-> DataAttemptStr в context
-> Orchestrator

    1. Выбрать поля для новой попытки

    Сначала нужно определить, по каким каноническим полям будет выполняться новая попытка.

    Попытка всегда задаётся через значения из PersonFields.

    Пример

    Допустим, нужна новая попытка поиска по ФИО и дате рождения.

    Тогда набор полей будет такой:

    [
    "surname",
    "namep",
    "patronymic",
    "dateBirth",
]

    Это должны быть именно значения полей из PersonFields, а не названия колонок источника.

    2. Добавить попытку в файл настроек

    Файл настроек попыток: config/erzl.toml

    В проекте попытки сейчас лежат в секции:

    [pipeline_steps.erzl.prepare_attempt_keys]

    Нужно добавить туда новую запись.

    Изменение

     [pipeline_steps.erzl.prepare_attempt_keys]
 snils_data = ["snils"]
+fio_birth_data = ["surname", "namep", "patronymic", "dateBirth"]
 dudl_fio_data = ["surname", "namep", "patronymic", "dudlTypeId", "dudlSer", "dudlNom", "countryDudl"]

    Что важно

    Порядок записей здесь важен.

    Именно в этом порядке попытки попадут в PrepareAttemptStepCfg, а потом будут вызываться через AttemptId:

    • попытка 0
    • попытка 1
    • попытка 2

    В примере выше порядок будет таким:

    1. snils_data
    2. fio_birth_data
    3. dudl_fio_data

    3. Подключить новую попытку в bootstrap

    Файл сборки конфига попыток: config/bootstrap_core_types.py

    После добавления попытки в TOML её нужно включить в attempts_by_name при создании PrepareAttemptStepCfg.

    Изменение

     _ERZLMainPrepareAttemptStepCfg = PrepareAttemptStepCfg.from_field_values(
     attempts_by_name={
         "snils_data": attempts_raw["snils_data"],
+        "fio_birth_data": attempts_raw["fio_birth_data"],
         "dudl_fio_data": attempts_raw["dudl_fio_data"],
     },
     field_enum=PersonFields,
 )

    После этого новая попытка попадёт в:

    PrepareAttemptStepCfg.attempt_fields

    и станет доступна для PrepareAttemptStep.

    4. Проверить, что поля попытки уже приходят в контекст

    Файлы, которые нужно проверить:

    • файл типов полей: Source/source_core_types.py
    • файл алиасов источника: config/erzl.toml
    • файл адаптера источника: Adapters/Adapters.py

    Чтобы попытка реально сработала, все её поля должны уже приходить в:

    ctx.SourceData

    То есть для каждого поля попытки должно выполняться следующее:

    1. поле существует в PersonFields;
    2. поле собирается адаптером RenameToSourceInputAdapter;
    3. у источника есть алиас на это поле.

    Пример

    Если вы добавили попытку:

    fio_birth_data = ["surname", "namep", "patronymic", "dateBirth"]

    то в алиасах источника должны уже быть такие поля:

    [adapters.erzl.person_fields_alias.main]
surname = ["Пациент Фамилия"]
namep = ["Пациент Имя"]
patronymic = ["Пациент Отчество"]
dateBirth = ["Пациент Дата рождения"]

    После адаптации строки источника должен собираться такой SourceInput:

    SourceInput[PersonFields](
    attributes={
        PersonFields.SURNAME: "Иванов",
        PersonFields.NAME: "Иван",
        PersonFields.PATRONYMIC: "Иванович",
        PersonFields.DATE_BIRTH: date(1980, 1, 1),
    },
    index=1,
)

    5. Как новая попытка проходит по пайплайну

    Файл шага подготовки попытки: Pipeline/pipeline_protocols.py

    Шаг PrepareAttemptStep берёт текущий индекс попытки:

    ctx.AttemptId

    и выбирает набор полей:

    self._cfg.attempt_fields[ctx.AttemptId]

    Дальше DataSelector пытается найти в ctx.SourceData все нужные поля текущей попытки.

    Если подходящие данные есть, результат записывается в context через ColumnSelectorAdapter, и в ctx.DataAttemptStr попадает набор полей текущей попытки.

    Пример ожидаемого результата

    Если текущая попытка:

    ("surname", "namep", "patronymic", "dateBirth")

    и все поля найдены, то в context будет записано:

    ctx.DataAttemptStr == (
    PersonFields.SURNAME,
    PersonFields.NAME,
    PersonFields.PATRONYMIC,
    PersonFields.DATE_BIRTH,
)

    6. Как попытка переключается дальше

    Файл orchestration попыток: Orchestrator/Orchestrator.py

    После выполнения PrepareAttemptStep orchestrator получает одно из решений:

    • CONTINUE
    • NEXT_ATTEMPT
    • NO_MORE_ATTEMPTS

    Как это работает

    Если поля найдены

    Orchestrator продолжает сборку search XML:

    SelectAttemptKeysDecision_StrEnum.CONTINUE

    Если для текущей попытки данных нет

    Orchestrator увеличивает AttemptId:

    self._adapter_base.attempt_plus_one(ctx)

    и запускает следующую попытку:

    SelectAttemptKeysDecision_StrEnum.NEXT_ATTEMPT

    Если попытки закончились

    Когда все попытки для текущего PersonType исчерпаны, orchestrator получает:

    SelectAttemptKeysDecision_StrEnum.NO_MORE_ATTEMPTS

    Дальше происходит одно из двух:

    1. если PersonType == MOSCOW, orchestrator переключает тип на NONRESIDENT и сбрасывает AttemptId в 0;
    2. если PersonType == NONRESIDENT, orchestrator ставит need_create = True.

    7. Минимальный набор файлов

    Чтобы добавить новую попытку, обычно меняются только два файла:

    • файл настроек попыток: config/erzl.toml
    • файл сборки конфига попыток: config/bootstrap_core_types.py

    Если используются уже существующие поля PersonFields и существующие алиасы источника, остальные файлы менять не нужно.

    8. Готовый пример целиком

    Шаг 1. Добавить попытку в TOML

     [pipeline_steps.erzl.prepare_attempt_keys]
 snils_data = ["snils"]
+ fio_birth_data = ["surname", "namep", "patronymic", "dateBirth"]
 dudl_fio_data = ["surname", "namep", "patronymic", "dudlTypeId", "dudlSer", "dudlNom", "countryDudl"]

    Шаг 2. Подключить её в bootstrap

      _ERZLMainPrepareAttemptStepCfg = PrepareAttemptStepCfg.from_field_values(
      attempts_by_name={
          "snils_data": attempts_raw["snils_data"],
+         "fio_birth_data": attempts_raw["fio_birth_data"],
          "dudl_fio_data": attempts_raw["dudl_fio_data"],
      },
      field_enum=PersonFields,
  )

    Шаг 3. Ожидаемый порядок попыток

    AttemptId = 0 -> snils_data
AttemptId = 1 -> fio_birth_data
AttemptId = 2 -> dudl_fio_data

    Шаг 4. Ожидаемое поведение

    • если в SourceData есть snils, отработает первая попытка;
    • если snils нет, orchestrator перейдёт ко второй;
    • если по второй тоже нет данных, перейдёт к третьей;
    • если попытки закончились, произойдёт смена PersonType или переход в create-flow.
