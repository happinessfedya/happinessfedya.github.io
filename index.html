    Общая структура проекта

    Текущая документация описывает ERZL-пайплайн в трех плоскостях:

    • Architecture объясняет границы слоев и жизненный цикл ERZL_Context.
    • Reference дает точные API-контракты Python-модулей.
    • How to показывает пошаговые изменения конфигурации, полей, попыток и сценарии отладки.

    Сейчас в docs задокументирован именно ERZL-пайплайн. Основная reference-страница одна: ERZL/reference/api.md.

    Как читать документацию

    • Если нужно понять общую архитектуру и границы ответственности слоев, начни с ERZL/architecture/overview.md.
    • Если нужно понять, как рождается, меняется и завершается ERZL_Context, открой ERZL/architecture/ERZLcontext-lifestyle-mermaid.md.
    • Если нужен точный контракт DTO, Protocol, step-классов, bootstrap-конфига или run-утилит, смотри ERZL/reference/api.md.
    • Если нужно внести точечное изменение в пайплайн, используй страницы из ERZL/how-to/.

    Карта страниц

    ERZL/architecture/overview.md

    Главная архитектурная страница проекта.

    Что дает:

    • показывает слои Source -> Adapters -> ContextFactory -> DataSelector -> XML -> Pipeline -> Orchestrator;
    • объясняет, где должна жить новая логика;
    • помогает не смешивать source-, adapter-, XML- и orchestration-ответственности.

    ERZL/architecture/ERZLcontext-lifestyle-mermaid.md

    Подробная страница про жизненный цикл ERZL_Context.

    Что дает:

    • объясняет, что именно хранит ERZL_Context;
    • показывает переходы между search-flow и create-flow;
    • фиксирует инварианты контекста и правила его изменения;
    • помогает читать состояние контекста при отладке.

    ERZL/reference/api.md

    Единая API reference-страница по Python-модулям проекта.

    Сейчас покрывает:

    • Source
    • Adapters
    • XML
    • Pipeline
    • Orchestrator
    • config bootstrap-слой
    • run утилиты запуска

    Важно:

    • config/erzl.toml не является Python-модулем и поэтому не рендерится через mkdocstrings;
    • структура TOML и логика активных профилей описаны в how-to странице ERZL/how-to/Добавить профиль активации в config.toml.md.

    ERZL/how-to/Добавить источник.md

    Пошаговая инструкция по добавлению нового источника данных.

    Что дает:

    • показывает, какие DTO и cfg нужны новому source;
    • объясняет, как подключить новый source в bootstrap;
    • показывает, где именно меняется LoadContextStep.

    ERZL/how-to/Добавить поле от источника до XML.md

    Пошаговая инструкция по прокидыванию нового поля через весь пайплайн.

    Что дает:

    • показывает путь поля от alias источника до XML;
    • фиксирует точки изменения в PersonFields, alias config, attempt config и XML mapping;
    • помогает не пропустить слой между источником и builder-ом.

    ERZL/how-to/Добавить попытку.md

    Пошаговая инструкция по добавлению новой search-попытки.

    Что дает:

    • показывает связь config/erzl.toml -> bootstrap -> PrepareAttemptStepCfg -> Orchestrator;
    • помогает корректно встроить новую попытку в текущий цикл поиска;
    • фиксирует минимальный набор затрагиваемых файлов.

    ERZL/how-to/Добавить профиль активации в config.toml.md

    Пошаговая инструкция по добавлению нового активного профиля в config/erzl.toml.

    Что дает:

    • описывает структуру [integrations.erzl] и связанных ref-блоков;
    • показывает, какие ключи обязательны для bootstrap;
    • помогает безопасно переключить активный профиль.

    ERZL/how-to/Отладить ответ ERZL.md

    Практическая инструкция по разбору проблемных ответов ERZL.

    Что дает:

    • показывает порядок проверки xml_bytes, response_bytes, rslt_container и ERZL_id;
    • помогает локализовать проблему в builder, transport, parser или orchestration;
    • дает готовые сценарии быстрой диагностики.
